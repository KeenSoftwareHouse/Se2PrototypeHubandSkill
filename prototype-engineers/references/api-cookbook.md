# SE2 API cookbook

Verified in game or by decompile across many prototypes on Space Engineers 2 **2.3**, **2.4** and
**4.0** (each entry under "Local discoveries" names its version). Names drift
between builds: treat every entry as a strong lead, and confirm with `api-search.ps1 -Decompile`
before building on it. Each section says where the state lives (**client** or **server** session).

## Plumbing

- **Plugin entry**: any public non-abstract class implementing `Keen.VRage.Core.Plugins.IPlugin`; ctor may take `PluginHost`. Loaded by `SpaceEngineers2.exe "-plugins:<a.dll>;<b.dll>"`. Deps (0Harmony.dll) resolve from the plugin's folder.
- **Engine thread**: `Singleton<VRageCore>.Instance.UpdateQueue.Enqueue(Action)` (also `Enqueue(Action, TimeSpan delay)` — a self-rescheduling chain gives a ~30 Hz loop without Harmony). Guard with `VRageCore.HasValue`. This queue is per **render frame**.
- **Sim tick**: `Keen.VRage.DCS.Scenes.Scene.Tick(bool)` runs all jobs for one scene. A Harmony prefix there is the place for per-tick input injection (the UpdateQueue would drop/duplicate deltas). Client and server scenes both tick it; tell them apart by the scene. Client tick rate is **not** fixed 60 Hz — measure with a Stopwatch.
- **Sessions**: `Engine.Scene.UserObject as GameCoreScene` → `GameClient.TryGet<WorldSessionComponent>().OwnedSession`. In single player `GameServer` is null; the server session is the other `WorldSessionComponent` in `coreScene.Entities` (template `Sessions.cs`). Server-scene access from the engine thread is legal between server ticks.
- **Enumerate**: `session.GetEntitiesOfType<CubeGridComponent>()`; `entity.TryGet<TComponent>()` returns component or null. Session components: `session.SessionComponents.TryGet<T>()`, or extension `session.Get<T>()` (needs `using Keen.Game2.Simulation.Utils; Keen.VRage.DCS.Accessors; Keen.VRage.Core.Game.Components`).
- **Entity data (unmanaged structs)**: `component.Data` / `entity.Data` is a `DEntityContext` with `Get/TryGet/Has/Set/GetWritePtr/TryRemove<T>`. Most live state is here, not on components.
- **Client ↔ server pairing**: no plain shared EntityId found. Working approaches: world-position match; `ReplayContext.TranslateObject` is the proper API (not yet used). Grids have no persistent ID — prototypes stored state as a `[Tag]` suffix on the grid name.
- **Namespaces that are easy to miss**: `Entity` = `Keen.VRage.DCS.Components`; `Session` = `Keen.VRage.Core.Game.Systems`; `GameCoreScene` = `Keen.Game2.Simulation.RuntimeSystems.CoreScenes`; `WorldSessionComponent` = `Keen.Game2.Game.SessionComponents`; `Vector3/Vector3I/Vector3D/Quaternion` = `Keen.VRage.Library.Mathematics` (no `VRage.Math.dll`; no instance `Length()` — use `Math.Sqrt(Vector3.Dot(v,v))`); `WorldTransform` = `Keen.VRage.Core`; `RayCastArgs` = `Keen.VRage.Core.Game.GameSystems.Queries`.
- **Keen types, not BCL**: `Keen.VRage.Library.Threading.Task<T>` (poll `IsCompleted` + `TryGetResult`; no `ContinueWith`). `Buffer<T>` (`Keen.VRage.Library.Memory`, IDisposable). `FixedPoint` → cast to `double`. `LocKey` is a struct (no `?.`). `LocalizableText.ToString()` for names.
- **Harmony**: works in-process (Lib.Harmony 2.3.6). Jobs are called through generated `*_InvocationStub` methods that call the real static method, so detouring the real method works. Private parameter types: declare as `object` or omit (Harmony matches by name). `Optional<T>` is a readonly ref struct (`.HasValue`, `ref .Value`). Overloaded targets: select by parameter types (`AccessTools.Method(type, name, new[]{...})`).

## Grids & blocks

- Blocks on a grid: `CubeGridComponent.VisitAllBlocksWithComponent<CubeBlockComponent>(b => ..., includeSubgrids: false)`. `b.Entity`, `b.Definition` (`CubeBlockDefinition`; `.DisplayName`, `.UIData.Name`), `b.AABB` (cells), `BlockOrientation`, `GetTransformedOccupiedCellGroups()`.
- Grid name: `CubeGridComponent.DisplayName` (LocalizableText). Rename from UI via `ControlPanelGridModel.DisplayName`.
- Whole ship (incl. subgrids): `grid.GetAllGridsInShip()`. Delete: `session.MarkEntityForClose(e)` (skip grids with `GridClosing` set).
- Ownership: `OwnershipComponent.Owner` (IdentityId, `GameSystems.Ownership`); `PlayersSessionComponent.IsPlayerIdentity(id)`.
- **Detecting placement/removal**: 1 Hz poll-diff of blocks per grid is the robust way (`IBlockPlacement.OnBlockAdded/RemovedSignal` are effects-only and miss deletes). Grids stream blocks in for ~30 s after load — baseline first. Survival holograms: `ProjectionSourceComponent.ProjectionData` — walk the whole bundle tree (`Builders` + recursive `eob.GetChildren()`, dedupe by reference). Projected block def: `eob.Definition.Definitions.OfType<CubeBlockDefinition>()`.
- **Materials**: `CubeBlockDefinition.Items` (`ImmutableArray<ItemAmount>{Item, Amount}`) is the fully computed recipe — merge duplicate item names (critical + optional repeat). Same-name blocks are size variants with different GUIDs.
- **Mass/HP/recipe math** (post-processed from model colliders): `Mass = Density.MassCurveModifier * sqrt(cells) * log10(cells) + MinBlockMass`; `MaxHealth = Fragility.MaxHPMassMultiplier * Mass`; recipe scale = round(Mass / Σ(Amount·MassPerUnit)); `BuildTime = BuildTimePerItem * TotalItemAmount`. `RecipeEfficiency` is authored but unused (2.4). Read results off `DefinitionManager`, don't recompute.
- Mirror/symmetry: `block.PlacerDefinition?.OverrideSymmetries ?? BlockPlacerConfiguration.DefaultBlockSymmetry` → `GetRotationToMirror(sign)`; planes in `BuildingInfoComponentObjectBuilder.SymmetryPlanes` (half-cell units, `int.MaxValue` = off).

## Flight & thrust

- **Max thrust per direction, already efficiency-scaled and replicated to the client**: grid `Data.Get<MaxThrustData>().Regular` → `Thrust6Directions{Positive(+X right,+Y up,+Z back), Negative}`. Don't iterate thrusters.
- Grid physics on `grid.Data`: `GravityEffectData.GravitySum` (m/s²), `RigidBodyMassProperties.Mass`, `RigidBodyData.LinearVelocity`, `data.GetWorldTransform()` (basis = `Vector3.Transform(UnitX/Y/Z, Orientation)`), `Has<DampeningData>()`.
- **Sustainable lift at current attitude** = `min over axes a with |u_a|>1e-3 of cap_a(sign u_a)/|u_a|`, u = world-up in grid space. (Summing projections over-counts; max single axis under-counts.)
- **Movement is simulated on the SERVER only.** Client `CockpitInputHandlerComponent` → grid `ControlData{Movement, Rotation}` (grid-local, analog 0..1, `[SyncFromClients]`).
- **All thrust math is one static job**: `ThrustComponent.ComputeThrust(DEntity, in MaxThrustData, ..., in ControlData, ..., EntityData<ActiveThrustData>, Writable<VoluntaryThrustData>, ..., Optional<CustomGravity>, ...)` (namespace `...WorldObjects.Shared.Movement`). Steps: max thrusts → dampening → gravity comp → input × capacity → clamp → soft speed limit → `ActiveThrustData.ComputedThrustPerFrame = force/60`. Postfix it to own the force.
- **Hover is not thrust**: the game cancels gravity by editing `CustomGravity.Value`. To own hover, capture CustomGravity in a prefix (`__state`) and write it in the postfix.
- **GravityMultiplier trap**: `PhysicsSessionConfiguration.GravityMultiplier` = 2 in content — bodies fall at 2×g while HUD/CustomGravity say 1×g. Hover the stock way (edit CustomGravity), or a thrust-based hover sinks at exactly 1×g.
- No thrust spool/ramp exists anywhere. Flame visuals = `VoluntaryThrustData` fraction.
- Gyros: prefix `GridGyroscopesComponent.ComputeTorqueAngular` / `ComputeTorqueTarget` (overloaded — pick the one whose first param is `DEntity`) and edit the `angularData`/`targetData` arg.
- Thruster consumption hooks: `ThrusterComponent.RecomputeConsumedResource`, `OnStartFiring`.
- Seat detection: `CockpitInputHandlerComponent.Activate/Deactivate` (2.4). Older: `CockpitHUDScreenViewModel` ctor + private `_gridEntity` (did not fire in 2.4).
- Docking/landing: `ConnectorComponent` (`WorldSpacePivotTransform` forward = out of face, `IsAllowedCounterpart`, `IsAlignedWellEnoughToConnectWith` 0.1 m/5°, `TryConnect`); built-in alignment motor `MechanicalBlockCounterpartAlignmentComponent.RequestStartAligning()`. Landing gear = `MagneticBlockComponent` (`ReadyToLockEntity`, `IsLocked`, `RequestLock()`). Grid `ParkingState` (Idle/CanPark/IsParked). P is stock-bound to ToggleParkingBrakes.

## Character & aim

- Local character: postfix `CharacterHUDComponent` (client, `GameSystems.CameraSystems.Adapters`) `IInSceneListener.OnAddedToScene`, read private `_character`.
- Pitch = `LookOffsetData.PitchOffset` (radians, + up, `[SyncFromClients]`, only while grounded). Writing it moves camera **and** bullets. Yaw = body rotation from `ControlData.Rotation.Y`, consumed per tick as a radian **delta** that persists — withdraw injected deltas next tick or the character spins. Inject from a `Scene.Tick` prefix.
- Game `Recoil` = physics impulse on the shooter, not gun kick. Spread = `MaxAngleDeviation*` cone.
- Shot signal (client-replicated): `ProjectileWeaponBaseComponent.ShotFiredWithProjectileOriginSignal.Subscribe(toolEntity, handler)`. Held tool: `character.Get<ToolsComponent>().CurrentTool`; `GunToolComponent.IsAimingDownSights`.
- Camera shake: `entity.AddCameraShake(power)` on the character, 0..15, a per-frame level (re-post each tick).
- **Character physics**: definition `CharacterPhysicsComponentDefinition` (private setters; recompute the `*Cosine` props after editing angles). Live per-tick: `CharacterMovementComponent.GroundModeData` (write via `Data.GetWritePtr`), `CharacterPhysicsData.SupportDistance` (free live override). Baked into Havok at creation: gravity alignment, slope, jump etc. → apply via **prefix on `CharacterPhysicsComponent.Init`**, then respawn/reload. **Never rebuild a character controller in place** (native crash / assert). Find all characters: postfix `RigidBodyComponent.OnAddedToScene`, filter `is CharacterPhysicsComponent`. Only one of the two SP copies owns a Havok controller.
- Content values differ a lot from code defaults (MaxSlopeAngle 65 vs 45, etc.) — always baseline from live definitions.

## Power & gas

All `[ServerOnly]` — read from the server session, publish snapshots to UI.
- **One read API**: `((IResourceNode)component).GetResources(buffer)` → `ResourceNodeData{Resource, Current, CurrentMax, TheoreticalMax, IsConsumer}`. Every producer and store implements it.
- Stores (battery **and** tank): `ResourceContainerComponent` — `ResourceType`, `CurrentChargeValue/MaxChargeValue`, `CurrentChargeLevel` (0..1), `CurrentChargeFlowRate` (+charging), `Mode` (Auto/Charge/Discharge).
- Producers: `SolarGeneratorComponent`, `WindTurbineComponent`, `ItemToResourceConverterComponent` / `AutoItemConverterComponent` (O2/H2 gen, reactor).
- Grid aggregate: `grid.TryGet<ResourceDistributorComponent>().TryGetResourceStats(StringId)` → `AvailableResources`, `ConsumedResources`. Power is demand-driven: producer `Current` always equals draw, so "consumed/produced" reads ~100% — use draw vs capacity for headroom.
- Units: `ResourceTypeDefinition.FlowRateUnits/StorageUnits.ToString()`.

## Production & items

- Every smelter/refinery/assembler has `ItemConverterComponent` (`...CubeBlocks.Production.ItemConverters`); `Definition.RecipeDefinitions` values → `ItemRecipesDefinition.Recipes` → `ItemRecipeDefinition{Inputs, Outputs, TimeToConvert}`. Queue: `converter.TryEnqueueRecipe(recipe, times)` (engine thread). No ingots in SE2.
- Build planner: `BuildPlanners.BuildPlannerData` (player-attached planned blocks).

## Conveyors & placement

- Ports = model dummies of type `ConveyorHole` / `UseConveyor` (`ConveyorSystemConfiguration.PipeableDummies`). Port size from `ModelDummy.Scale` X/Y (1.5 = large, 0.5 = small), per port not per block. Port transform = `blockRelTransform * dummy.Transform.Transform`.
- Cell lattice is **0.25 m**: `Vector3I.Round(4f*pos + 0.5f*dir)`, cell centres on integers.
- `ConveyorElementTranslator` (public static): `GetConveyorPath`, `TraverseFromDummy`, ... Grid `ConveyorSystemComponent.TryGetGroup(block, nodeId)` → connected component; `AreConnectedAsync`, `IterateReachableInventories`.
- **Programmatic placement**: build a grid EOB from `BlockPlacerEntityComponentDefinition.DefaultPrefabServerGrid`, add block EOB from `DefaultPrefabsPostProcessor.GetDefaultPrefabFor(def)`, wrap in `BlockPlacerEntityBundle`, call `BlockPlacerNetworkStories.PlaceOnGrid(clientGrid, bundle, volumes, default)`. Gotchas: pass the **client** grid (server grid silently does nothing); serialise placements; correct `Mountpoint` for rotation; in survival the first piece makes a hologram and the rest must use `PlaceOnProjection`.
- Legality/preview to reuse: `BlockPlacementClientSessionComponent` (`CheckPlacementIsPossible`, `DrawPlacementPreview`).

## Economy, PCU, GPS

- Credits: `session.Get<IPerPlayerData>().GetPerPlayerData<PlayerCreditsData>(identityId).ModifyCredits(float)`.
- Prices: `TradingStationInventoryDefinition.Items[item].Price`, fallback `EconomyConfiguration.DefaultItemPrices`.
- PCU: `PCUExtensions.GetPCU(grid)`; per player `PCUSessionComponent.GetPCU(id)` / `MaxPerPlayerPCU`.
- GPS: `GPSMarkersData.AddMarker(clientSession, new GPSMarkerParams(cfg.PlayerMadeMarkerType, name, pos, cfg.DefaultIcon, color, desc))`, `RemoveMarker(...)`. Markers are saved — tag yours and clean up on load.

## Terminal UI (G-screen)

Plain Avalonia MVVM; content can be any code-built control.
- **Sub-tab**: Harmony postfix on `Keen.Game2.Client.UI.TerminalScreen.TerminalScreenViewModel` ctor; build `new TerminalSubScreen(category, new TerminalScreenId("Grid/MyTab"), locKey, true, typeof(MyView), factory)`, insert into `vm.SubScreens` (private setter → reflection). Reuse an existing sub-screen's `.Category` (e.g. `TerminalScreenId.From(GridScreenMode.Production)`). Override header via `<LocalizedHeader>k__BackingField`.
- **Top-level category**: `new TerminalCategoryTab(new TerminalCategoryId("X"), locKey, true)` into `vm.Categories` (reflection); sub-screen ids "X/Name".
- The terminal's interacted grid: `vm.Interacted`.
- Avoid the game's `Expander` theme; build your own collapsibles. UI thread cannot read `[ServerOnly]` components — poll immutable snapshots published from the engine thread.

## HUD

- Overlay: `OverlayLayer.GetOverlayLayer(TopLevel)`; TopLevel = `(Application.Current.ApplicationLifetime as IClassicDesktopStyleApplicationLifetime).MainWindow`. Place with `Canvas.SetLeft/Top/Right/Bottom`. Receives input unless `IsHitTestVisible=false`.
- Add a row to the cockpit stat cluster: find visual descendant with type name `CockpitHUDResourceBars`, inside it the Grid containing a `HUDResourceBar`; add a RowDefinition + child. Re-inject on every seat entry (HUD is torn down on exit).
- World-space drawing: postfix private `GPSMarkerRenderSessionComponent.DrawHUDMarkers`, read `_cameraComponent/_renderContracts/_definition`, then `GetUISystem().CreateImmediateMainViewBatch(n)` → `DrawLine/DrawStringAligned` (`Keen.VRage.Library.Mathematics.Vector2`, `TextAlignmentEnum` in `Keen.VRage.Render.UI`).
- **Bitmaps**: SE2 uses a custom Avalonia platform. `new Bitmap(stream)` throws; use `WriteableBitmap`. Its `Lock()` stride is wrong (bits not bytes) — write tightly packed at `Width*4`; lay bytes out **R,G,B,A**; fill completely **before** assigning to `Image.Source`, and create a fresh bitmap per update (texture is read once).

## Particles

Client session: `...OwnedSession.SessionComponents.TryGet<ParticleEffectsSessionComponent>()`.
- `TrySpawnEffect(WorldTransform, ParticleEffectBaseDefinition, ParticleEffectUserParameters, null, ...)` → `ParticleEffectHandle?` (`UpdateParent(null, wt)`, `SetParameters`, `StopEmitting`, `Dispose`). Looping effects are never distance-culled.
- Defs: `Singleton<DefinitionManager>.Instance.TryGetDefinition(guid, out def)` / `GetDefinitionsOfTypeAndDescendants<ParticleEffectBaseDefinition>()`. Catalog: `GameData\Vanilla\Content\System\Particles\*.def`.
- `ColorMultiplier` only darkens coloured textures; only `TextureIsMonochromatic` emitters tint. Small particles vanish at km range whatever the scale.
- Custom effect without authoring: `def.DeepClone()`, filter `ParticleEmitters`, set private-setter props by reflection, spawn the instance directly.
- Camera position: private `_cameraTransform` on `ParticleEffectsSessionComponent`.

## Planets & star map

Client session, `Keen.VRage.Voxels.Components.VoxelPlanetComponent` on planet entities.
- `QueryMaterialAndBiome(localPos, lod, pinned)` → `{BiomeKey, MaterialKey, SampledHeight}`. **Bulk sampling: `pinned:false`, lod 2** (pinned = a streaming request per call, pathological in bulk). Budget ~8 ms per engine tick.
- Radii: `Radius`, `AtmosphereRadius` (actually inner radius), `RadiusWithMaxHills`, `ZeroGroundRadius` (sea level). Surface = inner + SampledHeight. `WorldToLocalPosition(Vector3D)`.
- `SphericalToVector3` / `Vector3ToSpherical` are **not inverses** (180° longitude off) — invert by hand.
- Biomes: `PlanetBiomeMapComponent.Definition.BiomeMap.SurfaceBiomes`; ocean key 200; ocean radius `PlanetaryWaterComponent.OceanLevelRadius`.
- Star map click: prefix `ColonizationMapSessionComponent.OnSelectSector` (postfix is too late), read `HoveredObject`, resolve through `GetDiscoveryForObject(obj).Discoverable is PlanetDiscoverable` → `Details.Location`.

## Physics queries

- Raycast: `session.Get<IPhysics>().CastRay(Buffer<SweepQueryHit>, in RayCastArgs{Position, Direction*len, IgnoredEntities}, CollisionPreset.Closest)`; async `CastRayAsync`. Hit body → `Entity.TryGetFromDataEntity(new DEntityContext(scene, hit.Body))`.
- Asteroids are not session entities — find them by raycast.
- Weather/wind exist server-side: `PlanetWeatherServerComponent`, `WindGeneratorComponent`.

## Definitions & content

- `Singleton<DefinitionManager>.Instance` (no `.HasValue`): `TryGetDefinition(Guid, out Definition)`, `GetDefinitionsOfTypeAndDescendants<T>()`, `GetConfiguration<T>()`, `GetPostProcessor<T>()`.
- Game content: `<SE2 root>\GameData\Vanilla\Content\**\*.def` — plain JSON; grep them for GUIDs, tuning values, and names. Content often differs from code defaults.
- Script components (no plugin): F12 → Gameplay → Attached Scripts: a C# class with a ctor taking `Entity` and an arg-less `Update()`.

## Local discoveries

These ship with the skill. Record your own findings in `%LOCALAPPDATA%\prototype-engineers\local-discoveries.md`, not
here: edits to the skill's files block its updates.
- [2.4.0.95] HUD/world drawing: `UI3DSessionComponent` (client session component, `Keen.Game2.Client.GameSystems.UI3D`) is the non-debug world-space line/quad/outline renderer. Draw only from a postfix on its `UpdateTransform` (draws outside UpdateTransform..Draw assert). Extensions in `UI3DDefaultRendering`: `DrawLine(Vector3D, ColorSRGB, Vector3D, ColorSRGB, float thickness)`, `DrawQuad(4x Vector3D, color)`, `DrawHighlightOutline(OrientedBoundingBoxD, color, thickness, cornerRatio)`. **Line thickness is screen PIXELS (half-width), not metres** - 0.02 is invisible; use 2-6. Quads are world-space. (seen in game)
- [2.4.0.95] Grid merge/fusion (no stock merge exists): serialize grid A's block entities as bundle roots (`session.EntitySerializer.Serialize(blocks, bundle, (e,_) => e.TryGet<CubeGridComponent>()==null && e.TryGet<CubeBlockComponent>()!=null && set.Contains(e))`), `CloneBundle()`, rewrite each root's `ChildTransformComponentObjectBuilder.Transform` (grid-local metres + quat) into B's frame, `EntityParents[stub] = gridB.Entity`, `session.Get<IEntitySpawner>().SpawnBundle(...)` on the SERVER session, then `MarkEntityForClose(A)`. Same path as block undo (`AddRemoveBlocksBase`); real blocks with state in any game mode. Worked from a server `Scene.Tick` prefix. (fused in game)
- [2.4.0.95] Driving a grid body: write `grid.Data.GetWritePtr<RigidBodyData>()` `LinearVelocity`/`AngularVelocity` (world, rad/s) on the SERVER from a `Scene.Tick` prefix - pushed to Havok before the step. `GridPhysicsComponent.SetAlwaysActive(true)` while held. Mass: `RigidBodyMassProperties.InvMass` (0 = static), `CenterOfMass` body-local. (seen in game)
- [2.4.0.95] Input: raw devices via `Engine.Get<InputEngineComponent>().DeviceManager.OnBeforeProcessInput += (dm) => dm.Keyboard/Mouse.GetDigitalState(KeyboardInputs.Home / MouseInputs.Left)`, wheel `GetAnalogState(MouseInputs.VerticalWheel)` = per-frame notches (±1). Swallow game actions with a prefix on internal `InputContext.Dispatch(InputActionDefinition action, InputControl, ControlActivation activation)` returning false by `action.Guid` (always pass End/Cancel). Zero walking with a prefix on `CharacterMovementControlComponent.RequestMovementChange(ref MovementInputs __0)`. Window focus/cursor: `Engine.Single<IPlatformWindows>().Window.IsActive/ShowCursor` (needs `using Keen.VRage.DCS.Components`). Home is unbound by the game but popular with plugins - read hotkeys through `PluginKeys` (template) so players can rebind them; key names resolve with `KeyboardInputs.TryGetInputFromName("Keyboard::X")` / `MouseInputs.TryGetInputFromName`, and a keyboard `InputId.Index` IS the Win32 virtual-key code. Numpad keys are `Numpad0..9`, `NumpadDivide/Multiply/Subtract/Add/Decimal`; the game binds most F-keys, Delete, [ ] and backtick.
- [2.4.0.95] Fast travel: server `FastTravelServerSessionComponent` (publicize Game2.Simulation): `StartFastTravel(ClientId, FastTravelFieldComponent)` sets `op.Timer` countdown -> private `PerformFastTravel(client)` (Result Confirmed = client blackout+video) -> `PrepareOperation` (anchor/collect/free space) -> `Teleport` (prefix it and return your own Keen `TaskCompletionSource` struct `.Task` to own placement). `_operations` dict is pollable per tick (the StartFastTravel postfix alone looked unreliable). "Sector not available" = `ValidateOperation` -> `LockedGameContent`. Config timings (`FastTravelFadingIn/Out`, `MinimumDuration`) have private setters. Countdown ring = `SessionInGameUISessionComponent.OpenFastTravelScreen`. `ISpaceProbeSystem.PreloadAsync` from there froze the main thread 27-60 s. (in game)
- [2.4.0.95] Composite after glass: transparent (OIT) is resolved in `SceneDrawSystem.ResolveOIT(commandList, lBuffer, ...)`, AFTER `HighlightJob.DoWork` - a HighlightJob composite leaves windows floating on top. Postfix ResolveOIT and use `__instance._eyeAdaptationJob.Exposure`.
- [2.4.0.95] Video as a shader texture: `session.Get<RenderContracts>().CreateVideoPlayerEntity(ResourceHandle<VideoAsset>)` (SetVolume, OnStateChanged PlayingDone - no loop, recreate); render thread `CoreSystems.Scene.TryGetEntity(entity.Id, out e)` -> `e.Get<VideoPlayerEntityComponent>().GetDrawableTexture()` (sRGB, engine updates every video texture each frame).
- [2.4.0.95] Safe zones: `SafeZoneComponent.WorldArea` (sphere), `ZoneName`; enumerate on server with GetEntitiesOfType. Terminal/map open: private `SessionInGameUISessionComponent._terminalScreen != null`. Seated characters are NOT parented to the seat and keep a stale body velocity; check `ISeatable.CurrentSeat`. Dampeners cancel added velocity - to move a piloted ship, drive toward a target velocity each tick.
- [2.4.0.95] Avalonia platform gaps (SE2 custom platform): `GeometryGroup` throws NotImplementedException in measure (`AvaloniaApp.CreateGeometryGroup`) and CRASHES the game - put several shapes in one `StreamGeometry` as separate figures. Geometry `Clip` is ignored (falls back to bounds) - draw pre-cut polygons instead. `OverlayLayer` + `Path`/`StreamGeometry` work fine.
- [2.4.0.95] HUD views built by precompiled XAML (e.g. `AmmoGroupView` inside `ProjectileWeaponScreen`) have their ctor INLINED - a Harmony ctor postfix never fires. Catch them with a postfix on virtual `Avalonia.StyledElement.OnDataContextChanged` filtered by type (fires reliably), or `Control.LoadedEvent.AddClassHandler`. Bindings on stock text re-push after `ClearValue` - hide the stock control and add your own.
- [2.4.0.95] Weapons/ammo: one inventory item = one magazine; `AmmoDefinition.Capacity` = rounds per magazine; `AmmoDefinitionsConfiguration.AmmoTypes` maps item -> AmmoDefinition (-> ProjectileDefinition). Hand guns (`GunToolComponent._inventory` IInventoryAdapter) reload from the character inventory only; block weapons (`ProjectileWeaponComponent._inventory`) from own + `ConveyorSystemComponent.IterateReachableInventories(inv, item, false, true)`. Creative/NPC skip inventory. HUD: `GunToolInputHandlerComponent.OnAddedToScene` -> `ProjectileWeaponScreenViewModel(Model)`; cockpit/turret groups -> `WeaponGroupScreenViewModel` (`_weaponEntities`, `_models`, `PerAmmoTypeData` one row per projectile). Client weapon entity has no ProjectileWeaponBaseComponent data worth reading; pair with server by world position (held tool lags 1.5-3 m while running).
- [2.4.0.95] UI3D TRAP: `UI3DDefaultRendering.DrawTriangle(...)` extensions (both overloads) recurse into themselves - `UI3DSessionComponent` has NO instance DrawTriangle, so the call binds back to the extension and the game dies with a stack overflow on first call. Draw triangles as degenerate quads: instance `ui.DrawQuad(a, b, c, c, color, depth)` (view-space Vector3 = world - `ui.CameraTransform`) or the per-vertex-colour quad. `DepthBehavior.Both` draws over the scene (view models). (crashed in game)
- [2.4.0.95] SP server runs on its own "In-Process Server Thread": the server `Scene.Tick` prefix is concurrent with the client render/update jobs. Do server physics raycasts only from the server tick and hand results to the client (don't raycast server physics from a UI3D postfix).
- [4.0] Ore deposits (server): `VoxelStorageComponentBase.GetMaterialDeposits(BoundingBoxD box, ImmutableArray<VoxelMaterialDefinition> ores, PooledList<VoxelMaterialDeposit> outList)` - the stock ore detector's own query (1 km sectors, a few ms). Deposits = merged clusters `{Material, Bounds}`. Ore list = union of `OreDetectorComponentDefinition.DetectableOreMaterials` (14 in 4.0: Chromium, Cobalt, Copper, Gold, Ice, Iron, Lead, Magnesium, Nickel, Platinum, Silicon, Silver, Titanium, Uranium). Voxel bodies: `server.GetEntitiesOfType<VoxelPhysicsComponent>()` -> `Components.OfType<VoxelStorageComponentBase>()`; asteroids stream in/out, so `ComputeCenteredTransform()` can NRE on one leaving - list fresh and try/catch per body.
